# 架构

## 三个流程

```text
启用主题 → 检查应用与运行时 → 保存本地设置 → 备份并接管快捷方式 → 持久启用
日常打开 → 原生入口 → 核验现有实例 → 冷启动动画 / 恢复后台窗口 → 主题注入
恢复默认 → 写入停用标记 → 暂停并撤下注入 → 按校验值恢复快捷方式
```

正式运行使用官方 Codex 可执行文件和一个独立的界面配置目录，不修改安装包，不复制账号文件。没有调试接口的已有实例只切回，不强行结束。恢复保留登录与后台任务，完整退出后再普通启动即可脱离受管实例。

## 职责

| 模块 | 职责 |
| --- | --- |
| 顶层两个 CMD | 定位源码版或使用包的管理入口，显示执行结果 |
| scripts/Manage.ps1 | 启用、恢复、持久状态与安装互斥 |
| scripts/Entrypoints.ps1 | 识别官方链接、备份原字节、安装、哈希校验恢复 |
| src/Launcher.cs | 小型原生入口，隐藏日常控制台，内部协调窗口显示 |
| scripts/Theme.ps1 | 应用身份、启动流程、壁纸和配色监视器生命周期 |
| scripts/Resume.ps1 | 核验进程、精确配置路径与浏览器身份后唤回后台实例 |
| src/WindowGate.cs | 首帧可显示前暂缓原生窗口，失败或超时后释放 |
| src/startup*.mjs | 只读取得原生标志定义、视频播放、暗色过渡、壁纸聚焦 |
| src/control-contrast.* | 深色控件和提示文字适配、刷新与新窗口跟随 |
| src/prepare-theme.mjs | 本机素材校验及不可变主题缓存 |
| scripts/Network.ps1 | 可选、仅作用于子进程的现有本机代理传递 |
| vendor/codex-dynamic-skin | 固定版本、未修改的 MIT 壁纸运行时 |
| scripts/Build-Release.ps1 | 按公开文件清单制作使用包、源码包与校验清单 |

所有持久数据在 `%LOCALAPPDATA%/CodexConanLauncher/`。`activation.json` 记录启用状态；`disabled` 阻止旧入口重新注入；`paused` 通知现有监视器清理；`entrypoints/manifest.json` 保存原快捷方式及安装后校验值。源码、压缩包均不包含这些数据。

## 恢复与故障边界

- 不修改全局 Codex 模型配置、系统代理或个人外观设置。控件配色为可撤下的注入样式。
- 恢复先持久停用，再清理界面和链接；即使活动界面无法核验，也不重新启用。
- 快捷方式在替换前写入备份日志，后续外部修改会阻止覆盖，原始备份保留。
- 标志呼吸来自原生定义，不以播放完成代表应用加载完成。
- 调试连接只接受本机地址，核验官方应用、端口归属、配置目录与浏览器身份。
- 只接管用户桌面和开始菜单入口，不宣称全系统拦截。原生界面有版本依赖，启动失败会放行原窗口。
- 当前主题不改变官方外观设置，建议用户自行选择深色以匹配标题栏。

## 开发验证

基础检查覆盖静态素材、第三方文件哈希、配置、脚本语法、媒体播放、可选代理及入口。`Test-Manage.ps1` 用隔离的快捷方式和状态目录验证反复启用/恢复、原设置保留及冲突保护。真实启动、超时释放和暖启动检查使用隔离配置与端口，仅结束测试自身创建且身份核验匹配的实例。
